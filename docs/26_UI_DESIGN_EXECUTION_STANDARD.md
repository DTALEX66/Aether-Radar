# 26 UI 设计执行规范

## 1. UI 总目标

Aether Radar 的 UI 要让用户一眼看出：这是一个专业、可信、可筛选、可评风险、可导出的 AI 生态选型平台。

不是普通导航站，不是 Logo 墙，不是只展示排行榜。

## 2. 页面设计原则

| 原则 | 要求 |
|---|---|
| 信息优先 | 每个卡片要展示用途、分类、热度、风险、来源、可用性。 |
| 风险前置 | 工具详情和对比页必须有风险模块。 |
| 筛选清晰 | 搜索、分类、风险、热度、开源、本地部署、国内可用性要容易操作。 |
| 导出可见 | 用户随时知道数据可以导出。 |
| 平台中立 | UI 不引导用户只用某一个笔记软件、coding agent 或模型。 |
| 商用谨慎 | 商用、许可证、隐私、版权要用清晰标签。 |

## 3. 核心页面蓝图

| 页面 | 核心 UI |
|---|---|
| 首页 | Hero、数据健康、核心入口、高热工具、场景方案、高风险关注、分类覆盖。 |
| 工具库 | 左侧/顶部筛选器 + 工具卡片 + 风险/热度/来源标签。 |
| 工具详情 | 基本信息、用途、风险矩阵、导出、替代品、场景、来源。 |
| 词汇百科 | 术语卡片、直译、中文名、解释、相关工具。 |
| GitHub 热榜 | Stars/Forks/维护状态/License/风险，不只按 Stars。 |
| 风险中心 | 风险分类、风险解释、高风险工具、用户核验清单。 |
| 场景方案 | 场景目标、工具组合、路线、成本、难度、风险、替代方案。 |
| 对比页 | A/B 差异、适用人群、成本、风险、推荐结论。 |
| 导出中心 | JSON、CSV、Markdown、Excel、Notion、飞书、PDF、API、MCP 路线。 |
| UI 系统 | 设计令牌、组件注册表、页面蓝图、AI UI 提示词。 |
| 规范中心 | 产品、品牌、UI、工程、数据、安全、发布规范总览。 |

## 4. 组件规范

| 组件 | 必备信息 |
|---|---|
| EntityCard | 名称、直译、分类、说明、热度、风险、开源、本地部署、国内可用性。 |
| RiskBadge | 风险等级：低/中/高/未知，颜色统一。 |
| HeatBadge | 热度等级：SSS/SS/S/A/B/C/未知。 |
| SourceBadge | 官网/GitHub/论文/平台公开/人工判断。 |
| ScenarioCard | 场景、人群、工具组合、成本、难度、风险。 |
| CompareCard | A/B 适合谁、关键差异、推荐结论。 |
| ExportCard | 格式、适合人群、导出限制、后续规划。 |
| DataHealthBar | 实体数、分类数、最后更新、已审核比例、风险覆盖率。 |
| PageHero | 页面名、定位、主操作、次操作。 |

## 5. 视觉层级

1. 页面标题：说明用户现在能完成什么。
2. 关键操作：搜索、筛选、导出、查看风险。
3. 数据卡片：工具/方案/风险/对比。
4. 免责声明：清楚但不喧宾夺主。
5. 二级链接：来源、详情、外部官网。

## 6. 响应式规范

- 桌面端：左侧筛选 + 右侧结果，或顶部筛选 + 卡片网格。
- 平板端：筛选器折叠为顶部区域。
- 手机端：单列卡片，筛选控件垂直排列。
- 不使用横向滚动承载关键功能，表格移动端要转卡片。

## 7. AI UI 生成规范

给 Lovart、v0、Figma AI、Cursor、Codex 的提示词必须包含：

1. 项目定位：全链路 AI 生态选型平台。
2. 必备模块：热度、风险、来源、场景、导出。
3. 品牌视觉：雷达、星图、信任评分、风险分层、数据卡片。
4. 禁止项：不要普通导航站、不要只做 Logo 墙、不要过度赛博风、不要只突出某一个工具。
5. 可编程要求：组件化、响应式、可绑定 JSON 数据、可导出。

## 8. UI 评审清单

每个页面必须通过：

- 是否保留风险标签？
- 是否有来源或更新时间？
- 是否支持用户自主选择？
- 是否体现平台中立？
- 是否使用统一组件？
- 是否可响应式？
- 是否避免空洞营销语？
- 是否可以被 Codex 按组件实现？
