# 24 产品执行规范

## 1. 产品定位

Aether Radar 是一个全链路 AI 生态导航、索引、筛选、风险提示、方案生成、导出接入和持续更新平台。

它不是普通 AI 工具导航站，也不是只服务某个 coding agent、笔记软件或模型平台的资料库。

## 2. 核心目标

1. 帮用户发现 AI 工具、平台、开源项目、模型、Agent、协议、工作流、知识库、设计/视频/编程工具。
2. 帮用户理解新兴 AI 术语、工具用途和生态位置。
3. 帮用户筛选：热度、风险、开源、本地部署、国内可用性、商用可用性、API/MCP 支持。
4. 帮用户对比：A vs B、国外工具 vs 国内替代、云端方案 vs 本地方案。
5. 帮用户做场景方案：文化墙设计、小游戏、企业知识库、本地助手、自动化推送、AI 短视频、Agent 接工具。
6. 帮用户导出和接入：Excel、CSV、JSON、Markdown、Notion、飞书、PDF、API、MCP、浏览器插件。
7. 帮用户持续追踪：GitHub 热度、平台状态、风险变化、价格/许可证/隐私政策变化。

## 3. 用户分层

| 用户 | 需求 | 产品入口 |
|---|---|---|
| 普通 AI 用户 | 快速找工具并避坑 | 工具库、风险中心、精选推荐 |
| 设计师 | 设计/绘图/视频/素材工作流 | 设计类工具、场景方案、UI 生成 |
| 开发者 | 开源项目、Agent、API、MCP、本地部署 | GitHub 热榜、API/MCP、数据导出 |
| 运营/内容用户 | 写作、短视频、自动化、发布 | 场景方案、工具对比、自动化类目 |
| 项目经理 | 选型、汇报、对比、导出 | Excel/PDF、对比页、商业风险 |
| 企业用户 | 私有化、合规、团队白名单 | 风险中心、企业版路线、内部工具库 |
| AI 学习者 | 学术语、搭知识库 | 词汇百科、Markdown/Notion/飞书导出 |
| AI Agent 用户 | 让 Agent 查询生态数据 | JSON、API、MCP Server |

## 4. 产品模块边界

### 必须做

- 工具库
- 词汇百科
- GitHub 开源热榜
- 风险中心
- 场景方案库
- 工具对比库
- 导出中心
- 平台收录数量榜
- UI 生成系统
- 数据状态页
- 免责声明
- Agent 交接规范

### 暂缓做

- 用户社区
- 评论系统
- 大规模爬虫
- 自动付费系统
- 企业 SSO
- 浏览器插件完整实现
- 复杂 AI 推荐模型

### 不做

- 不直接替用户购买或授权。
- 不承诺某工具绝对安全。
- 不承诺生成内容可商用。
- 不收集敏感企业数据作为默认功能。

## 5. 产品判断公式

一个功能是否值得做，按以下公式判断：

`价值 = 选型帮助 + 风险透明 + 可导出/可接入 + 可持续更新 - 维护成本 - 安全风险`

如果一个功能只增加页面数量、但不能帮助用户判断和落地，优先级降低。

## 6. 全量收录与精选推荐

| 模式 | 含义 | 用户提示 |
|---|---|---|
| 全量收录 | 覆盖更多工具、平台、项目、名词 | 覆盖面更广，风险需自查 |
| 精选推荐 | 人工审核、来源明确、风险标注完整 | 可优先参考，但仍需核验官网条款 |

页面必须明确区分，避免用户把“被收录”误认为“被推荐”。

## 7. 项目验收口径

每个新版本必须回答：

1. 用户能不能更快找到工具？
2. 用户能不能更清楚看到风险？
3. 用户能不能导出或接入自己的系统？
4. 数据有没有来源、时间和可信度？
5. Codex/其他 Agent 接手是否更省上下文？
