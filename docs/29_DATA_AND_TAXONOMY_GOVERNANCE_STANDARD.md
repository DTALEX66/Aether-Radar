# 29 数据与分类治理规范

## 1. 数据目标

数据必须支持用户做选择，而不是只增加数量。

每条数据都要尽量回答：

- 它是什么？
- 属于什么类别？
- 热度如何？
- 风险如何？
- 适合谁？
- 是否开源？
- 是否本地部署？
- 是否支持 API/MCP？
- 是否可商用？
- 来源是什么？
- 最后核验时间是什么？

## 2. 主数据源

`data/seeds/*.json` 是唯一源数据。

`next-app/data/*.json` 和 `static-site/data/*.json` 是镜像数据，不能长期作为主数据修改。

## 3. Entity 必备字段

| 字段 | 说明 |
|---|---|
| `id` | 稳定唯一 id。 |
| `name` | 原名。 |
| `literalTranslation` | 直译。 |
| `cnName` | 常用中文名。 |
| `category` | 主分类 id。 |
| `summary` | 一句话解释。 |
| `helpsWith` | 能帮助 AI/用户做什么。 |
| `heatLevel` | SSS/SS/S/A/B/C/Unknown。 |
| `riskLevel` | 低/中/高/未知。 |
| `isOpenSource` | 是否开源。 |
| `localDeployable` | 是否本地部署。 |
| `chinaAvailability` | 国内可用性。 |
| `sourceUrl` | 来源链接。 |
| `sourceType` | 官网/GitHub/论文/平台公开/人工判断。 |
| `sourceConfidence` | 高/中/低。 |
| `reviewStatus` | 待审核/已审核/精选推荐/谨慎使用/已过期。 |
| `pricing` | 免费/Freemium/订阅/按量/企业版/未知。 |
| `license` | MIT/Apache/GPL/AGPL/商业闭源/未知。 |
| `commercialUse` | 可商用/需核验/不建议/未知。 |
| `dataPrivacy` | 云端/本地/可选/未知。 |
| `recommendedFor` | 适合人群。 |
| `lastVerifiedAt` | 最后核验日期。 |

## 4. 分类原则

分类不能无限膨胀。新增分类前必须满足至少一个条件：

1. 已有 5 个以上实体无法合理归入现有分类。
2. 用户有明确筛选需求。
3. 它影响风险或商用判断。
4. 它对场景方案有独立价值。

## 5. 去重规则

同一实体只能有一个主 id。

以下情况视为同一实体：

- 同一官网。
- 同一 GitHub repo。
- 同一产品的中英文名。
- 同一工具在不同类目下重复出现。

允许多分类，但不允许复制多条主实体。

## 6. 热度规则

GitHub Stars 只是一项关注度指标。

热度判断应结合：

- Stars
- Forks
- 最近更新时间
- Releases
- Issues 活跃度
- Contributors
- 平台公开用户量
- 社区讨论热度
- 国内可用性
- 是否仍维护

## 7. 风险规则

风险维度包括：

- 隐私
- 版权
- 商用
- 许可证
- 安全
- 维护
- 国内可用性

风险高不代表不能用，而是需要明确提示。

## 8. 数据状态

| 状态 | 含义 |
|---|---|
| 候选 | 还未人工检查。 |
| 已审核 | 基本信息和来源已核验。 |
| 精选推荐 | 适合优先展示，但仍需风险提示。 |
| 谨慎使用 | 有明显风险或限制。 |
| 已过期 | 工具下架、项目归档或信息明显失效。 |

## 9. 更新频率

| 数据 | 建议频率 |
|---|---|
| GitHub 指标 | 每日/每周。 |
| 平台价格 | 每月。 |
| 许可证 | 每月或版本变更时。 |
| 隐私政策 | 每月或重大更新时。 |
| 国内可用性 | 每月。 |
| 场景方案 | 每月复核。 |
| 新工具候选池 | 每周。 |

## 10. 数据发布前检查

- 是否有 id？
- 是否有来源？
- 是否有风险等级？
- 是否有核验日期？
- 是否重复？
- 是否分类正确？
- 是否同步到前端数据？
- 是否通过 `validate_data.py`？
